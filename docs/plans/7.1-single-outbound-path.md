# Phase 7.1 Single Outbound Path & Bridge Protocol Plan

## 1. Objective and Architectural Seam
Consolidate all outbound communication paths across WhatsApp and future channels into a single, strictly audited pipeline via `dispatch_with_rechecks()`. Eliminate all un-gated HTTP call sites (`POST /send_message` in `app/main.py` and direct assistant execution in `app/dashboard.py`).

## 2. Inbound and Outbound Wire Protocol Specification
Bridge and core backend communication uses strict HMAC-SHA256 signatures over length-prefixed fields to prevent delimiter-injection attacks:
- **Draft ID**: Serialized strictly as a decimal string (`draft_id = "1042"`), never a raw integer or JSON number.
- **Timestamp**: Integer Unix seconds serialized as a decimal string (e.g. `"1775894400"` <!-- # fake-test-number -->), valid within a $\pm 300\text{s}$ tolerance window.
- **Length-Prefixed Payload**: Canonical payload representation:
  `canonical = f"{len(channel)}:{channel}|{len(draft_id)}:{draft_id}|{len(chat_id)}:{chat_id}|{len(timestamp)}:{timestamp}|{len(text)}:{text}"`
- **Shared Test Vectors**: Core Python and Node.js bridge share deterministic test vectors in `tests/fixtures/bridge_vectors.json`.

## 3. Node Bridge Test Harness Pre-requisite
Bridge protocol enforcement requires Node-side verification before production traffic gating:
1. **Node Automated Unit Suite**: Implement `whatsapp-bridge/test/protocol.test.js` exercising canonical formatting, signature calculation, and timestamp drift rejection before updating bridge production handlers.
2. **Bridge Signature Verification**: Implement constant-time comparison in Node (`crypto.timingSafeEqual`) matching Python `hmac.compare_digest`.

## 4. Single Funnel Architecture
All outbound transmissions route strictly through `dispatch_with_rechecks()`:
```
[User Action / UI / Bot]
         │
         ▼
[DraftRepository.transition_state(draft_id, HELD -> APPROVED)]
         │
         ▼
[dispatch_with_rechecks()]
  ├─ 1. Global kill switch check (FAILCLOSED) -> HELD (ABORTED)
  ├─ 2. Shadow mode re-verification -> SHADOW_LOGGED
  ├─ 3. Per-chat cooldown & rate limiter check -> HELD (COOLDOWN)
  ├─ 4. Atomic SQLite state transition -> SENDING
  ├─ 5. ChannelAdapter.send_text()
  └─ 6. Transition -> SENT or SEND_UNKNOWN
```

3. `repoint legacy approvals routes to unified dispatcher pipeline`
4. `route dashboard direct send through draft repository and safety gate`
