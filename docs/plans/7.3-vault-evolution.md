# Phase 7.3 Vault Scope & Evolution Plan

## 1. Architectural Scope Decision (Lead Architect Directive)
For GhostReply v0.1, the cryptographic KDF is intentionally **not** upgraded:
- **Rationale**: No Telegram session file or live MTProto credentials exist yet in the codebase. WhatsApp operates via the loopback Node bridge without session vault coupling.
- **Decision**: Retain standard library `hashlib.scrypt` ($N=16384, r=8, p=1$, salt=32 bytes, dklen=32 bytes, blob header `b"GR1"`) for v0.1.
- **Deferral**: Migration to a hardened KDF (either `scrypt` with raised parameters $N=2^{17}, r=8, p=1$ with a dynamic `GR2` header, or `Argon2id` requiring external C dependencies) is formally deferred to the future Telegram integration lane when real session strings are introduced.
- **Reference**: OWASP Password Storage Cheat Sheet recommendations for memory-hard KDFs: [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

## 2. Phase 7.3 Work Scope
Rather than modifying cryptographic primitives prematurely, Phase 7.3 focuses on documentation integrity and defensive hardening:
1. **Documentation Alignment**: Reconcile all repository documents (`docs/ARCHITECTURE.md`, `docs/RUNBOOK.md`, `SECURITY.md`) to accurately document `scrypt` rather than claiming unimplemented Argon2id defaults.
2. **Fail-Closed Persistent Lockout**:
   - The lockout state machine in `app/security/vault.py` must fail closed if the persistent state file (`data/vault_lockout.json`) is unreadable, corrupted, or encounters I/O exceptions.
   - When any state read error occurs, the vault must raise `VaultLockoutError` and treat the system as locked rather than failing open.
3. **Record ADR-005**: Formalize ADR-005 in `docs/DECISIONS.md` documenting the accepted v0.1 scrypt baseline and the deferred Telegram lane evolution criteria.

## 3. Threat Model and Boundary Analysis
- **What Is Protected**: Decrypted keys and tokens reside in volatile process memory only. The lockout mechanism throttles brute-force attempts on local unlock (5 attempts / 15-minute persistent lockout).
- **Residual Risk**: $N=2^{14}$ provides standard protection on low-end systems but does not reach the modern OWASP recommended minimum for high-assurance offline storage ($N=2^{17}$). Deferral is justified strictly because no live credentials currently exist in storage.

## 4. Implementation Roadmap
1. `harden vault lockout state handler to fail closed on io and json errors`
2. `align architecture documentation to reflect current scrypt baseline`
3. `record adr-005 status and evolution trigger in decisions index`
4. `add automated tests verifying fail-closed lockout on corrupt state files`
